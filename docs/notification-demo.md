# 信用通知演示与接入范围

页面分为历史账单分析、本月消费与信用通知、财务评估与购买决策。财务条件集中设置。

## 当前可用入口

- 上传手机采集端导出的 JSON 文件（单条对象或对象数组）。
- `window.CashMesh.receiveNotification(object)`：浏览器内接入函数，并非 HTTP 地址。
- “模拟通知演示”按钮：明确标记来源，可清除关联模拟记录。

当前未提供远程接收服务或 iPhone 常驻采集，不宣称持续自动同步。手机采集端需另行接入，现场可使用文件上传或模拟按钮。

## 字段

`id` 为通知唯一标识；`platform` 为美团月付、抖音月付、花呗、白条或信用卡；`timestamp` 为通知日期时间；`amount` 以元为单位；`kind` 为 expense、refund、repayment 或 statement；`transactionId` 为交易标识；`originalTransactionId` 用于退款和还款关联；`dueDate` 可选，不提供时不会猜测。

## 统计口径

最近30天展示通知，本自然月展示消费预算。购买占用消费预算，还款只影响现金流；出账通知作为快照保留，不能再次累计成消费。退款与还款需要原交易关联，证据不足集中提示。待核对信用义务不等同于银行确认的账户待还余额。

通知重复 ID／同平台交易 ID 会去重。与历史账单以明确交易 ID，或精确时间、商户、平台及金额关联；不按同日同额直接合并。保留原记录用于追溯，统计排除已关联副本。缺失付款方式或交易标识的跨来源重复仍可能存在，分析不能视为完整账户审计。

## 验证

`node tests/notifications-dom.mjs` 覆盖通知幂等、跨来源关联、同额不同订单、出账、退款、还款、缺失证据、模拟清理及决策联动。另运行现有账单、消费分析、预算和异常处理回归测试。尚未完成真实浏览器或手机端持续同步验收。
